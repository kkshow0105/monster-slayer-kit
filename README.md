## 使用与部署

本地直接打开 `index.html` 可使用普通导航和涨跌幅计算器。PWA 安装、离线缓存和更新需要 HTTPS 或 localhost，不能使用 `file://` 验证。

将 `index.html`、`manifest.webmanifest`、`sw.js`、`assets/`、`tools/` 一起发布到普通 HTTPS 静态托管，支持根目录或子目录。保持发布地址和目录稳定。服务器需正确提供 JavaScript、PNG 和 manifest 文件，不要把缺失文件重写为首页。

建议为 `sw.js` 设置 `Cache-Control: no-cache`；其他未带内容哈希的静态文件也应允许重新验证，避免配置长期 `immutable` 缓存。发布时尽量整批上传；资源缺失会使新版安装失败，旧版仍然可用。

在 iPhone Safari 打开网站首页，选择分享菜单中的“添加到主屏幕”，如出现“作为网页 App 打开”选项，开启后添加。首次联网打开并完成缓存后，首页和三个工具页面可离线打开；汇率换算需要此前成功获取并保存过汇率。最终 iPhone Safari/主屏幕体验需部署后真机验收。

## 发布新版本

1. 修改代码后，只在 `sw.js` 中递增 `APP_VERSION`，采用 `v主版本.次版本.修订版本`。
2. 提交、推送后，将整个项目发布到原有静态托管地址。
3. 应用打开、回到前台或恢复联网时会检查更新，同一页面的显式检查间隔至少一分钟。首次安装不显示更新提示。
4. 新版本完整缓存后，四个页面都会显示底部提示。点击“立即更新”才请求等待中的 worker 接管，并刷新当前页面一次。失败时可重试，不会清空 localStorage。

保持应用打开时，新版会等待点击；如果所有旧页面都已关闭，浏览器也可能按标准 Service Worker 生命周期在下一次打开前完成激活。其他已打开页面不会被强制刷新，重新打开后使用新版。

旧实现没有更新提示，而且使用自动激活。本次首次迁移后，如果已有旧安装仍显示旧页面，请关闭该网站所有 Safari 页面和主屏幕 App 后重新打开，让等待中的新 worker 接管。无需删除主屏幕图标或清空数据。后续版本即可使用更新按钮。

缓存按应用路径和版本区分，只清理本路径的过期静态缓存；旧版 `monster-slayer-kit-v数字` 缓存确认含本路径首页后才清理。第三方汇率 API 沿用原来的联网请求与 localStorage 回退，不进入静态缓存。

## ATR 补仓计算器（v1.2.0 正式版）

首页第三个入口，独立页面为 tools/atr-calculator/index.html。沿用原生页面、共享样式和 assets/app.js，没有新增运行依赖、账号、行情请求或后端。原有工具脚本与公共样式未修改。sw.js 已纳入新增页面、两个脚本和工具样式，正式版本与缓存版本均为 v1.2.0，已通过人工操作验收。发布收尾仅整理版本与验证，不调整已验收功能或界面。静态部署由使用者自行执行。

### 使用

填写名称、真实开仓价格和手动读取的 ATR，可选填代码和周期。默认 14 日、3 档 0.3/0.5/0.7 ATR；各档相对上一档累计扣减。可增删至 1～20 档，倍数必须大于 0。价格、ATR 与倍数支持最多 8 位小数，价格/ATR 不超过 10 亿，倍数不超过 100 万；周期可留空或填写 1～1000 日整数。计算过程使用 BigInt 定点数，保留 16 位乘积，仅最终显示时四舍五入为价格 4 位、跌幅 2 位。

首次开仓与每档默认计划仓位均为 10%，每项可改为 0～100%。超过 40% 会提醒，但仍允许生成。已执行仓位按首次开仓加勾选档位计算。

实时预览不保存计划，也不恢复草稿。点击“生成补仓明细单”才保存参数与结果快照。修改输入和“清空重置”均不改变既有计划。重置有输入时先确认，并恢复原来的 14 日、首次仓位 10%、三档 0.3/0.5/0.7 ATR、每档仓位 10%。

每份计划可独立查看、按档确认实际成交价、纠正记录、结束、复制和二次确认删除。点击“确认补仓”展开价格输入，默认填当前参考价，最终确认后锁定实际成交价和确认时间；取消或确认前刷新不会保存成交草稿。确认顺序从最早未执行档位开始，不允许跳档。超过计划价 10% 的偏离仅提醒，不拒绝合法真实成交价。

创建时的价格和 ATR 快照不变。实际成交后，尚未执行档位从最近已确认真实成交价接续计算；累计跌幅仍相对首次开仓价。卡片保留创建时计划价；如果确认时参考价已有调整，也单独保留。下一档距离仅表示从上一笔成交价到目标价的计划跌幅，不代表实时行情。

“纠正记录”先明确确认，再进入编辑；保存时记录前后价格和时间。后面已确认的真实价格及确认时参考价不受早期记录纠正影响。合法真实成交价使后续价格不大于 0 时仍保存真实记录，相关目标显示为“—”，提示重新评估；不会伪造负数补仓参考价。已结束计划保留历史并只读查看；复制按原始快照创建独立新轮次，全部成交状态和纠正记录重置。

status 为 active（进行中）或 ended（已结束）。snapshot 始终保留创建时参数与参考价格，completed 保留每档执行状态。新增 executionVersion、executions 和 dynamic：

- executions 中未执行档位为 null；已执行记录保存 actualPrice、confirmedAt、referencePrice（确认时参考价）、legacy 和 corrections。纠正历史保存 before、after、at；确认时间不被纠正时间覆盖。
- dynamic 保存当前各档参考价、累计跌幅、已完成档的实际价格展示、最近成交基准 base、下一档 next 及异常标记。目标无效或旧成交价未知时采用 null，不保存负数目标。
- 价格、代码、倍数、仓位和计算结果用字符串保存，周期为整数或 null；内部定点计算精度不变。

兼容读取 version 1 与 2。打开旧计划时只在内存中补充结构，读取本身不写入。旧已勾选记录保留 completed=true，actualPrice 和 confirmedAt 为 null，明确显示“实际价格未记录”，不以计划价冒充真实价。进行中计划可用“补录实际价格”记录真实价格；补录后才允许新的接续确认。旧版跳档执行状态也保留，补录后按顺序补齐前面未执行档位；补齐前不展示含混的下一档距离。结束的历史记录只读保留，不要求补录。

首次成功操作时在同一键中写入 version 2，保留原 ID、创建时间、参数快照和旧执行状态。旧版应用不识别 version 2 时会按原保护机制只读报错，无法覆盖新记录，请在其他旧标签页也完成更新。

写入成功后才更新页面；读取失败、不兼容版本、快照/成交记录损坏或重复 ID 时保护原数据，禁止覆盖，可识别记录仍可只读查看。空间不足或存储禁用会明确报错，不把失败当作保存成功。多标签页通过存储事件同步，写入前检查是否已有其他页面修改。

数据只属于当前来源（域名/协议/端口）和浏览器存储空间。本地测试数据不会自动同步到正式网址或其他设备；清理网站数据、卸载 PWA 或更换设备可能丢失，第一版不含导入导出。

### 手工验收

从项目目录启动本地服务（已有 Python 时）：

~~~powershell
python -m http.server 3000 --bind 127.0.0.1
~~~

1. 打开 http://127.0.0.1:3000/，进入 ATR 工具；若同地址已有旧版缓存，先点击更新提示。
2. 输入科创50ETF、0.583、0.026，确认三档为 0.5752、0.5622、0.5440。
3. 生成计划，点击“确认补仓”，输入实际成交价并确认锁定；刷新后检查记录、时间、仓位和后续参考价。
4. 试点第二档确认（第一档未确认时应提示），取消价格输入，及“纠正记录”的确认/取消；检查纠正历史和已完成档位保护。
5. 换另一只ETF生成计划，再切换两份计划查看，确认参数独立。
6. 复制、结束、查看历史并尝试删除（先取消，再确认），确认其他计划保留。
7. 首次联网完成缓存后测试离线；返回其他工具再进入，确认计划仍在。

额外示例：首次 1.1080、ATR 0.0430、三档均 0.4，原计划应为 1.0908/1.0736/1.0564；第一档成交 1.0880 后为 1.0708/1.0536，第二档成交 1.0710 后第三档为 1.0538。点“清空重置”确认原有默认值恢复，已保存记录仍在。旧计划已有执行标记时，只补录确知的真实成交价。

本地 Windows 浏览器可直接验收。真正的 iPhone Safari/主屏幕 PWA 需可从手机访问的可信 HTTPS 地址，待确认后安排，静态托管部署由使用者自行执行，本次不部署或修改线上配置。
